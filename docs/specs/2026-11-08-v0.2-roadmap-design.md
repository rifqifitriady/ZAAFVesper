# ZAAFVesper v0.2 design: active response, network, outputs, Sigma, Windows and Linux

Status: proposed 8 Nov 2026, awaiting owner approval.

## Owner decisions this design rests on

| Topic | Decision |
|---|---|
| Live validation (old Fase 1) | Skipped for now. Every v0.2 feature is built on a base that has never run live as root. That risk is accepted and stated in the README. |
| Protection | **Active response** that works without Apple's Endpoint Security entitlement. Real pre-execution blocking (AUTH) waits for the entitlement. |
| ZAAFElegia | NDJSON events with Sigma field names, plus OCSF Detection Finding alerts. These work with `zaaf hunt -` today. |
| Execution | The shared contract is frozen here first. Each workstream then runs in its own session and branch, ending in one PR. |
| Linux source | Sysmon for Linux, which shares its decoder with Windows Sysmon. |
| Earlier decisions (1B, 2B, 3B, 4) | Kill after an exec into a platform binary; launchd-parented prompt is CRITICAL; per-rule alert aggregation; defaults unchanged. |

## Hard limits, stated once

- **No blocking without the entitlement.** Without `com.apple.developer.endpoint-security.client`, nothing on macOS can block an action before it happens. Active response contains damage *after* the event. The README must never claim prevention.
- **Network telemetry polls sockets.** Without a NetworkExtension, ZAAFVesper polls socket tables, so it misses connections shorter than the polling interval, and DNS queries are not visible on macOS.
- **No live testing.** Windows and Linux code is cross-compiled and tested against decoder fixtures only. No Windows or Linux host is available here.

## Workstreams

### W1 · Active response (macOS)

New opt-in rule actions. They are enabled together with `kill` by `--enable-response`, and every one has `--dry-run-response`.

| Action | Effect | Guard rails |
|---|---|---|
| `quarantine_file` | Moves the event's file into a root-only vault `/var/db/zaafvesper/quarantine/<sha256>` (0700), with exec bits stripped and a JSON sidecar (original path, owner, mode, xattrs, rule, time). | The file must be bound to the event's dev/ino. Regular files only, opened `O_NOFOLLOW`. Never under `/System`, `/usr` (except `/usr/local`), `/bin`, `/sbin`, `/Library/Apple`, or any Apple-signed bundle. A size cap applies. Never the sensor's own files. |
| `requarantine` | Re-adds `com.apple.quarantine` to a file whose quarantine attribute an untrusted process removed, so Gatekeeper assesses it at the next launch. | Same file binding. Platform-protected paths are skipped. |
| `remove_persistence` | Takes a LaunchAgent or LaunchDaemon plist written by an untrusted process: runs `launchctl bootout` on its label in the right domain, then quarantines the plist. | Only `*/LaunchAgents/*.plist` and `*/LaunchDaemons/*.plist`. Never Apple labels (`com.apple.*`) or a plist owned by a platform binary. |
| `isolate_process` | Blocks the process's network through a pf anchor `com.rifqifitriady.zaafvesper`, using the remote addresses W2 observed for it. A time-to-live applies (default 1 h). | Never loopback or the configured management allow-list. The anchor is flushed at start and at clean shutdown. |
| `suspend` | Sends SIGSTOP immediately, so a kill or quarantine decision does not race the payload. | The same identity checks as `kill`. Resumes after a bounded time if no other action follows. |

Restore commands: `zaafvesper quarantine list|restore <id>` and `zaafvesper isolation list|release`. All actions share the per-rule and global budgets and raise `response_rate_limited`. Built-in rules that get actions: dropped untrusted binary run from temp (`quarantine_file`), quarantine stripped by an untrusted process (`requarantine`), Launch Agent or Daemon written by an untrusted process (`remove_persistence`), and the critical osascript prompt (`suspend` then `kill` of the parent).

### W2 · Network telemetry and outputs

**Network (macOS, no entitlement).**
- `pkg/source/netpoll` walks the sockets of every process in the table every `--net-interval` (default 1 s) and on each exec, using `proc_info` (PROC_PIDLISTFDS plus PROC_PIDFDSOCKETINFO).
- It emits `NetworkConnect` (outbound, established) and `NetworkAccept` (listen or inbound) once per socket.
- New rules: shell or interpreter with a socket to a remote peer (reverse shell); unsigned binary from temp connecting out; script interpreter connecting to a raw IP on an uncommon port.

**SIEM outputs (`pkg/output`).**
- syslog RFC 5424 over TCP and TLS (CA pinned);
- HTTPS webhook (JSON batches, bearer token read from a root-owned file);
- Splunk HEC mode of the webhook.

All outputs:
- share a disk spool, capped and root-owned, used while the endpoint is down;
- send alerts and, optionally, events;
- go through the sanitiser and the per-alert cap.

**ZAAFElegia.**
- `--elegia-out PATH|-` streams every event as NDJSON with Sigma field names (from `pkg/sigmamap`).
- Each record also carries `logsource.product`, `logsource.category`, a Sysmon-compatible `EventID` and `UtcTime`.
- `--alerts-ocsf PATH` writes alerts as OCSF Detection Finding (class 2004), matching ZAAFElegia's own output.
- `integrations/zaafelegia/` documents `zaafvesper run --elegia-out - | zaaf hunt -r <sigma rules> -`.

### W3 · Sigma import

- `zaafvesper sigma convert <sigma dir> -o <rules dir>` converts Sigma rules into ZAAFVesper rules through the `pkg/sigmamap` tables.
  - Products: macos, windows, linux.
  - Categories: those listed in the contract.
  - Modifiers: `contains`, `startswith`, `endswith`, `all`, `re`, `cidr`, `windash`, `exists`.
  - Conditions: `and`, `or`, `not`, `1 of`, `all of`, `them`.
- Anything unsupported is skipped with a reason, in a report (text and JSON).
- Converted rules keep the Sigma id, title, ATT&CK tags, level→severity, author and references. That last part is required by DRL 1.1 for SigmaHQ rules.
- Semantics are tested against ZAAFElegia's language-neutral conformance cases wherever the feature is supported.
- A small curated macOS set from SigmaHQ is converted and shipped in `rules/sigma/macos/`, with the DRL notice.

### W4 · Windows adapter, then Linux

**Shared decoder.** `pkg/source/sysmon` is a platform-neutral Sysmon XML decoder. It maps event IDs onto the canonical events: 1, 3, 5, 6, 7, 8, 10, 11, 12–14, 15, 17/18, 19–21, 22, 23/26, 25.

**Windows** (`GOOS=windows`):
- `pkg/source/winevt` subscribes to `Microsoft-Windows-Sysmon/Operational` through `EvtSubscribe` (wevtapi.dll via `x/sys/windows`, no cgo).
- Process bootstrap uses a Toolhelp32 snapshot.
- Kill uses `TerminateProcess`, after checking the process creation time and ProcessGuid.
- Runs as a Windows service.
- Ships with a recommended sysmon-modular configuration.

**Linux** (`GOOS=linux`):
- `pkg/source/sysmonlinux` reads Sysmon for Linux from journald (`journalctl -f -o json`, pinned binary, fixed argv) through the same decoder.
- Process bootstrap reads `/proc`.
- Kill checks the start time in `/proc/<pid>/stat`.
- Ships a systemd unit.

**Rules.** `rules/windows/` and `rules/linux/` start with converted SigmaHQ rules (W3) plus a few hand-written ones. Every rule declares `platforms:`.

## Shared contract (frozen before the sessions start)

Owned by the integrator; the sessions request changes and do not edit it.

1. **`pkg/event`.**
   - **New event names:** `NetworkConnect`, `NetworkAccept`, `DNSQuery`, `ImageLoad`, `DriverLoad`, `RegistryCreateKey`, `RegistryDeleteKey`, `RegistrySetValue`, `RegistryRename`, `PipeCreate`, `PipeConnect`, `WMIEvent`, `ProcessTamper`, `FileStreamCreate`.
   - **New event fields:** `Event.Platform` (`evt.platform`: macos, windows, linux).
   - **New structs:** `Net` (`net.*`), `DNS` (`dns.*`), `Registry` (`registry.*`) and `Module` (`image.*`).
   - **Windows process fields:** `guid`, `hashes`, `integrity`, `company`, `product`, `description`, `original_name`.
2. **`pkg/sigmamap`.**
   - Sigma (product, category) maps to canonical events.
   - Sigma field names map to ZAAFVesper fields.
   - Both directions, data only, tested so that every target field exists in the event registry.
3. **`pkg/rules`.**
   - Optional `platforms: [macos|windows|linux]` on a rule. `run` skips rules for other platforms; `rules test` tests all of them.
   - Rules are loaded recursively from subdirectories.
   - The action names are reserved now: `kill`, `quarantine_file`, `requarantine`, `remove_persistence`, `isolate_process`, `suspend`. Their validation and behaviour belong to W1.
4. **Decoder default.** The eslogger decoder sets `Platform = "macos"`.

## Sessions and file ownership

| Session | Branch | Owns (new files unless noted) | Shared files it may touch minimally |
|---|---|---|---|
| S1 Active response | `feat/active-response` | `pkg/response/*` (actions), `cmd/zaafvesper/response_actions.go`, `cmd/zaafvesper/quarantine.go`, `packaging/` (vault dir), built-in rule actions | `cmd/zaafvesper/run.go`, `main.go` (wiring and subcommand registration only) |
| S2 Network and outputs | `feat/network-outputs` | `pkg/source/netpoll`, `pkg/output/*`, `cmd/zaafvesper/outputs.go`, `rules/network_*.yml`, `integrations/zaafelegia/` | `run.go` and `pipeline.go` (wiring only) |
| S3 Sigma import | `feat/sigma-import` | `pkg/sigma`, `cmd/zaafvesper/sigma.go`, `rules/sigma/` | `main.go` (subcommand registration only) |
| S4 Windows, then Linux | `feat/windows-linux` | `pkg/source/sysmon`, `winevt`, `sysmonlinux`, `pkg/ps/*_windows.go`, `*_linux.go`, `pkg/response/identify_windows.go`, `identify_linux.go`, `rules/windows`, `rules/linux`, `packaging/windows`, `packaging/linux` | build tags in existing files |

**Gates for every session:**
- **Build and test:** `go vet`, `go test -race`, `CGO_ENABLED=0` builds for darwin, plus windows and linux where relevant, `rules validate` and `rules test`, and `make test-yara`.
- **Engineering judge:** SPEC, then VERDICT, with at most 3 rounds.
- **Independent security review.**
- **README and ledger:** honest updates.
- **Merging:** each session ends in a PR. The integrator merges in this order: S3, then S2, then S1, then S4. S1 depends on S2's network data for `isolate_process`. Until S2 lands, S1 implements that action against the contract and tests it with fixtures.

## Out of scope for v0.2

- AUTH (blocking) mode.
- A NetworkExtension.
- An eBPF Linux source.
- A network ingest API in ZAAFElegia (a follow-up in that repo).
- Correlation rules in ZAAFElegia.
