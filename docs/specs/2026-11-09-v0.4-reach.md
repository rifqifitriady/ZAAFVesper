# ZAAFVesper v0.4 design: reach

Status: requested by Rifqi on 9 Nov 2026 ("jalankan roadmap: response di windows/linux, linux tanpa sysmon, integrasi ZAAFElegia lebih dalam dan perluasan deteksi"). Validation on Rifqi's own Mac is removed from the roadmap at his request.

The roadmap is renumbered: v0.4 is **Reach** (this document), v0.5 is **Trust** (Developer ID signing; needs an Apple Developer account) and v0.6 is **Prevent** (Endpoint Security AUTH and NetworkExtension; needs Apple's entitlements).

## Workstreams (one session and one PR each)

| WS | Session | Branch | Delivers |
|---|---|---|---|
| E | S1 (active response) | `feat/response-win-linux` | Containment on Windows and Linux to match macOS. **Windows:** `isolate_process` via a Windows Filtering Platform or `netsh advfirewall` rule group owned by ZAAFVesper (pinned binary, fixed arguments, time to live, never the gateway, DNS or loopback); `quarantine_file` into an ACL-locked vault; `remove_persistence` for Run/RunOnce keys, services and scheduled tasks written by an untrusted process; `suspend` via `NtSuspendProcess`. **Linux:** `isolate_process` via an nftables table owned by ZAAFVesper; `quarantine_file`; `remove_persistence` for systemd units, cron entries and shell rc files; `suspend` via SIGSTOP with pidfd. The same guard rails apply everywhere: re-check identity, protected system paths, budgets, dry run. Live tests run on GitHub runners through the existing `live-response` workflow. |
| F | S4 (Windows/Linux) | `feat/linux-ebpf` | A Linux event source that needs no Sysmon: eBPF programs (CO-RE, BTF) loaded with `cilium/ebpf` (pure Go loader; BPF C compiled with `bpf2go`, generated objects committed so normal builds need no clang). Coverage: exec, exit, fork, file open/create/rename/unlink, setuid changes, ptrace and process_vm access, kernel module load, connect/accept, and DNS from UDP 53 where feasible. Events map to the existing canonical events, so every Linux and Sigma rule works unchanged. Sysmon for Linux stays as an alternative source. Bounded ring buffer, drop counters raise `es_events_dropped`-style `SensorDegraded`. Live validation on `ubuntu-latest` with Atomic Red Team. |
| G | S2 (network/outputs) | `feat/elegia-integration` | Deeper ZAAFElegia integration within ZAAFElegia's own scope: ZAAFElegia v0.1 deliberately has no daemon or network ingest, so the integration stays file and stream based. **ZAAFVesper side:** a versioned event schema for ZAAFElegia (`integrations/zaafelegia/schema/`); rotating NDJSON segment files (`--elegia-dir`) for scheduled hunts; Sigma correlation rules written for ZAAFVesper events (ready for ZAAFElegia M2); an end-to-end test in CI that builds `zaaf` at a pinned commit. **ZAAFElegia side:** one small PR adding a `zaafvesper` pipeline preset, a logsource doc and sample events, coordinated with whoever owns ZAAFElegia's current milestone, touching no engine code. A network ingest for ZAAFElegia is a separate decision for Rifqi in that repository. |
| H | S3 (Sigma/CI) | `feat/detection-expansion` | More coverage where it is thin, starting with the tactics that have the fewest rules. **macOS:** Exfiltration, Lateral Movement, Impact and Collection. **Windows/Linux:** credential access, lateral movement and defense evasion. Hand-written rules where the event model allows, more converted SigmaHQ rules with fixtures, each rule mapped to current ATT&CK IDs and, where an atomic exists, linked and exercised in the live workflows. A coverage report in CI (techniques per platform, rules without atomics) and a performance benchmark at high event rates. Target: from 63 to at least 90 ATT&CK techniques without lowering fixture quality. |

## Rules (as for v0.3)

- **Contract.** `pkg/event`, `pkg/sigmamap` and `pkg/rules` stay frozen. Request changes from the integrator in the PR. F may need new event fields for eBPF-only data; agree them first.
- **Gates.** Every PR passes:
  - CI (`ci.yml`) green;
  - `go test -race`;
  - cross builds;
  - `rules validate` and `rules test`;
  - the `judge` skill;
  - an independent `security-expert` review.
- **Live testing.** Live tests run only on throw-away GitHub runners, through `workflow_dispatch` or `validate/**` branches. Actions are pinned by SHA, permissions are least privilege, and no secrets are used.
- **Files and docs.**
  - README changes are proposed in the PR description; the integrator applies them.
  - Each workstream keeps to its own files and documents honest limits.
- **Merge order.** E and H as they become ready; then F; G last, because it depends on ZAAFElegia's state.
