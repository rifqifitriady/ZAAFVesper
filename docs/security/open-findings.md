# Security findings ledger (as of 8 Nov 2026)

Threat model: malware running as the owner's normal account (uid 501) that controls event content and every user-writable file. Sources:
- security re-review round 2 (H1, H2, M1–M7, Low);
- independent reviews of the fixes (round 3: F1–F10; round 4: New-1 to New-5);
- the engineering judge;
- the owner's decisions of 8 Nov 2026 (New-3, F3 residual, R5-1, default budgets).

Nothing has been exploited or validated live. Nothing was run as root during review. Plan and decisions: [docs/plans/2026-11-08-security-round2.md](../plans/2026-11-08-security-round2.md).

Status values:
- **Closed (code)**: fixed and covered by the named tests; live validation still pending.
- **Partial**: mitigated; the residual is stated.
- **Open**.

## Medium

| # | Finding | Status | Mechanism and evidence | Residual |
|---|---|---|---|---|
| M1 | The pre-kill identity check used process-controlled `kern.procargs2`. | **Closed (code)** | Right before the kill:<br>• **Kernel unique id.** The kernel's `p_uniqueid` (proc_info flavor 17) must equal the value the process table recorded when it first saw the process. A missing, unreadable or different id refuses the kill.<br>• **Start time** must match within 1 ms.<br>• **Protected image.** A platform binary at event time is refused. The current image's protection comes from the kernel: `proc_pidpath` protected paths, protected names on a platform image, and unreadable `csops` or path (fail closed).<br>• **Exec into a platform binary after detection** (owner decision 8 Nov 2026, New-3): allowed when the image at event time was not a platform binary and the unique id and start time match; the decision's detail records it. This applies only to events from the eslogger source, whose `is_platform` is reported by Endpoint Security (security note N1); `KillProc` and non-eslogger events refuse, and pkg/ps now copies the whole image identity, `IsPlatform` included, when a fork or later event carries no executable (`TestImageCopiedWithPlatformFlag`, `TestESSourceMatchesDecoder`, `TestVerifyPlatformAtEventBackup`, `TestExecIntoPlatformBinary`; real exec of a copied binary into `/bin/sleep` in `TestKillEvasionRealProcesses/exec_into_platform_binary_after_detection`, which also showed that `p_uniqueid` and the start time survive exec on this Mac).<br>• **Rename, delete or replace** of the executable is logged and does not save the process.<br>• **Team ID without a reported signing category:** refused.<br>If a process execs again before its earlier exec event is handled, that earlier incarnation has no recorded id and a kill on it is refused (fail closed; no rule kills the target process today). Tests: `TestGuardRails`, `TestExecIntoPlatformBinary`, `TestKillEvasionRealProcesses`, `TestIdentifyChild`, `TestIdentifySelf`, `TestKillParent`, `TestUniqueIDRead`. | `KillParent` races a parent that exits first. **Owner decision 8 Nov 2026 (New-3):** a detected process that execs into an Apple platform binary is killed (see Mechanism); pid 1, launchd, ZAAFVesper's own pids, eslogger, protected paths and protected names stay refused. Residual: if the process execs again before the sensor records its unique id for the earlier exec, the kill is refused (no recorded id), so a fast exec still escapes the kill (not the alert). On macOS where Endpoint Security does not report the signing category, killing a process that has a Team ID only raises an alert. |
| M2 | A process-table flood evicted a malware's parent, downgrading a CRITICAL rule. | **Closed (code)** | • Args, env and cmdline are shed before eviction, and the identity skeleton is kept (`TestFloodKeepsParentSkeleton`, `TestSkeletonEvictionLastResort`).<br>• `proctable_pressure` reaches the capture end to end (`TestProcTablePressureEndToEnd`).<br>• An unknown parent counts as untrusted (`TestUnknownParentIsNil`, rule fixtures).<br>• A double fork counts as untrusted through `ps.original_ppid` (`TestReparentedKeepsRealParent`).<br>• An untrusted ancestor anywhere in the chain counts as untrusted through `ps.ancestors_untrusted` (`TestAncestorsUntrusted`, SEC-R4 fixtures). | **Owner decision 8 Nov 2026 (F3 residual):** a credential prompt whose parent is launchd (ppid 1, parent `/sbin/launchd`; a LaunchAgent start or a double fork) is an untrusted origin through macro `launchd_parent`: the critical rule fires and the high rule does not (rules 1.4.0; fixtures in `rules/testdata/credential_access_osascript_password_prompt*.yml`, mutation-checked; Terminal -> zsh -> osascript stays high). It stays alert-only, because the kill target is launchd (`TestKillParent` "launchd parent ... refused"). A double-forked prompt only raises an alert for the same reason. `original_ppid` from live eslogger is unconfirmed. |
| M3 | YARA scanned whatever was at the path when the worker ran. | **Partial** | • Exec and file scans are bound to the event's dev, ino and ctime (`TestExecScanBoundToExecStat` with a matching replacement file, `TestFileScanBoundToEventStat`).<br>• A ctime-only change on a written file is scanned (`TestChmodAfterCloseStillScanned`).<br>• An executable deleted while its process still runs is reported (`TestExecGoneWhileRunningReported`).<br>• Reports are limited per (condition, pid or path), so one decoy does not hide another (`TestDecoyThenRealReplacementBothReported`). | A payload that unlinks itself, forks and exits the original pid within the queue latency is counted (`exec_gone`) but neither scanned nor reported. If eslogger's stat shape or precision differs live, exec scans report replacement or go unbound (counted as `exec_unbound`). |
| M4 | A self-signed binary can carry another vendor's Team ID. | **Closed (code)** | `cs_validation_category` is decoded, with a gate on ES message version 10 or later (`TestCSCategoryAndExeStat`). Every Team ID trust also requires `developer_id` or `app_store` (rule fixtures with `local_signing` and with the category absent). An unreported category fails closed. | Not validated live against a forged Team ID. |
| M5 | The `--json` alert file had no cap. | **Partial** | • Per-alert cap in one pass; identity is never cut; signing fields are capped at 256 B (`TestEncodePaddedAlertFastAndKeepsIdentity`, `TestEncodeCapsSigningFields`).<br>• File cap with rotation (`TestJSONLRotates`).<br>• Files younger than 7 days are never pruned (`TestOutputDirPrunePolicy`).<br>• High and critical alerts have their own file series and budget, plus a stderr fallback line while JSONL is stopped (`TestOutputDirBudgetFullOfYoungFiles`).<br>• eslogger `global_seq_num` gaps raise `es_events_dropped` (`TestSeqGapReported`). | **Owner decision 8 Nov 2026 (R5-1):** alerts are aggregated per rule per minute. The first 20 alerts of a rule in a minute, and the first alert of every new source after that (source = parent executable for a kill-parent rule, otherwise executable plus parent executable; at most 64 sources), are written in full to the console and both JSONL series; repeats of a seen source are replaced by ONE summary alert per rule (same rule id and severity, `"aggregated": true`, `"count"`, top five sources, and pid/ppid/exe/parent exe of the last three held alerts) at the end of the minute, on the rule's next alert, and at shutdown. Response is still evaluated for every alert. Memory is bounded (64 sources per rule, 512 rules). Tests: `TestAggregationDecoysDoNotHideRealPrompt`, `TestAggregationDiversifiedDecoysDoNotHideSource`, `TestAggregationFullLinesBounded`, `TestAggregatorFloodOneRule`, `TestAggregatorSummaryOnNextAlert`, `TestAggregatorBoundedMemory`, `TestSummaryEncoding` (pkg/alert); `TestAggregationEndToEnd` (100 alerts: 20 full + 1 summary of 80 in each series, second rule untouched, 100 response decisions, kill budget unchanged), `TestRunPipelineAggregates`, `TestReplayAggregatesByEventTime` (cmd). The new-source rule (first alert of every new source written in full) was added after the independent security review (finding 1) on top of the owner's 20-a-minute decision. One rule now writes at most about 84 full alerts and one summary a minute per series. That slows a single-rule flood but does not stop it: at up to 64 KiB per alert, a sustained flood still fills the 1 GiB high series in about 3 hours (7-day floor). When a rule's 64 source slots fill up in a window, a `SensorDegraded` event `aggregate_sources_exhausted` is raised (never aggregated; `TestSourcesExhaustedReportedOnce`, `TestSourcesExhaustedRaisesDegraded`). **Owner decision 8 Nov 2026 (New-1 / M5 defaults):** the budgets stay as they are (main 8 × 256 MiB, high 4 × 256 MiB, 7-day floor). Residual: an attacker who controls many executables or parents can still invent up to 64 decoy sources per rule per minute; after that, alerts from further new sources and repeats of seen sources are held, and the summary names only the top five sources by count and the last three held alerts, so a real alert placed after 64 decoy sources and followed by three more decoys appears only as a count (security review finding 2, low: it costs 64 alerts written in full and raises `aggregate_sources_exhausted`). Many different high rules firing together still add up (41 rules × up to 85 lines a minute); a low-severity flood across rules can still stop the main series for up to 7 days (New-1); `SensorDegraded` alerts are not aggregated (already limited to 120 a minute). Off-host shipping is the complete fix. |

## v0.2 S4: Windows and Linux adapters (preview, 9 Nov 2026)

Independent security review of the Sysmon adapters before the PR. Nothing here
was run on a Windows host or with Sysmon for Linux; the Linux code ran in a
container (unit tests, pidfd kill, a replayed journal).

| # | Finding | Status | Mechanism and evidence | Residual |
|---|---|---|---|---|
| S4-1 | Windows accepted any event carrying Sysmon's provider name; ETW providers are not authenticated, so a forged event 1 plus a kill rule could make the LocalSystem sensor kill a chosen process. | **Closed (code)** | The source accepts only events whose `Execution/@ProcessID` is a running Sysmon service's pid (SCM) and `Security/@UserID` is S-1-5-18; others are dropped and raise `sysmon_events_untrusted` ([winevt_windows.go](../../pkg/source/winevt/winevt_windows.go) `provenance`, `TestFeeder` trust case). The subscription also filters on the provider. | Untested on Windows; assumes the event log fills Execution and Security from the writer, not from the payload. |
| S4-2 | Windows output directory could be redirected through a junction above it, giving arbitrary create or delete as SYSTEM. | **Closed (code)** | CheckOwnership refuses any reparse point among the ancestors on the literal path; the output directory is held open without FILE_SHARE_DELETE; install steps create `C:\ProgramData\ZAAFVesper` with a SYSTEM/Administrators-only ACL first. | Untested on Windows. File operations inside the directory are by path (safe while only SYSTEM and Administrators can write there). |
| S4-3 | One control character or invalid UTF-8 byte in a command line made an event fail to parse, silently. | **Closed (code)** | `Sanitize` replaces characters XML forbids with U+FFFD before parsing; unreadable events raise `sysmon_events_unreadable` (`TestControlCharactersDoNotDropEvents`, fuzz seeds). | What Sysmon itself emits for such characters is not verified. |
| S4-4 | Escaping could push a legitimate event over the 256 KiB limit and drop it. | **Closed (code)** | Limit raised to 1 MiB (journald lines 6 MiB); oversize events are reported (`TestLongestCommandLinesFit`). | |
| S4-5 | Protected processes matched by base name, case-sensitively, so malware named lsass.exe or sysmon could not be killed. | **Closed (code)** for Windows and Linux | Windows: protection by full image path, case-insensitive, plus IsProcessCritical (`TestProtectedWinImage`). Linux: protected paths only (`TestLinuxProtected`). The macOS name list (launchd, eslogger, ...) is cleared on Windows and Linux. | macOS keeps its name list (S1's area). |
| S4-6 | The identity map was cleared when full; then a FIFO evicted the oldest (long-running) process first. | **Closed (code)** | Least-recently-seen eviction: a process that keeps producing events survives a flood of creates (`TestBinderEvictsOldest`). | A process silent for 65 536 other process starts loses its identity (kill refused, fail closed). |
| S4-7 | Repeated System header elements were accepted (last one won). | **Closed (code)** | Refused (`TestRepeatedHeaderRejected`). | |
| S4-8 | The journalctl child's pid stayed protected after a restart. | **Closed (code)** | Protected only while running (responder DynamicPIDs). | macOS eslogger keeps the old pattern. |
